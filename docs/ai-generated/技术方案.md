# 图片素材制作网站技术方案

> 文档状态：开发前基线方案  
> 依据：《小影科技2027校招-全栈开发笔试题 · 卷面》及需求沟通  
> 新增约束：提供简单账号密码登录；不开放注册；用户由数据库初始化或管理员直接维护  
> 最后更新：2026-11-08

## 1. 需求背景

本项目实现一个可独立运行的图片素材制作网站。用户登录后浏览模板，按模板要求上传图片并创建制作任务。Java 后端在 HTTP 请求结束后继续执行“素材检查、模拟生成、结果整理”三个阶段，前端持续查询任务状态，并展示个人历史、成功结果或失败原因。

项目不接入真实 AI。所谓“生成图片”是可控制耗时和失败阶段的模拟过程，成功结果使用项目内预置的示例图片。题目考察重点是：

1. Java 后端多步骤异步任务的组织、状态转换和持久化。
2. 前端对上传、提交、任务轮询、多任务隔离和查询异常的管理。
3. 登录用户与个人素材、个人任务之间的数据隔离。
4. 测试、CI、容器化和说明文档组成的完整工程交付。

### 1.1 核心业务流程

```text
登录
  → 浏览/筛选模板
  → 查看模板详情
  → 按要求上传图片
  → 创建制作任务并立即获得 taskId
  → Java 后台依次执行三个阶段
      素材检查 → 模拟生成 → 结果整理
  → 前端查询未完成任务
  → 展示成功结果或失败原因
  → 刷新后从后端恢复个人历史与未完成任务
```

### 1.2 范围边界

本期实现：

- 用户名、密码登录及当前用户查询。
- 数据库预置用户，不开放注册。
- 模板列表、分类筛选和模板详情。
- 图片选择、预览、替换、移除、上传及前后端校验。
- 创建异步制作任务。
- 三阶段后台模拟处理。
- 指定阶段失败与阶段耗时配置。
- 多任务状态查询、历史记录和刷新恢复。
- 成功结果图片预览。
- 核心自动化测试、CI 和 Docker Compose 交付。

本期不实现：

- 真实 AI、真实图片合成、视频处理。
- 用户注册、找回密码、短信/邮箱验证、第三方登录。
- 角色权限后台和用户管理页面。
- 模板 CRUD 管理后台。
- 下载、删除、重新制作和失败重试。
- 支付、积分、会员、国际化。
- Redis、消息队列、SSE、WebSocket、对象存储。
- 服务重启后自动恢复执行中的任务、断点续跑和严格受理幂等。

## 2. 建设目标

### 2.1 功能目标

1. 用户能够使用数据库预置账号登录，并只能查看自己的素材和任务。
2. 用户能够浏览来自 Java 接口的模板，并按分类筛选。
3. 用户能够上传满足模板数量、类型和大小要求的图片。
4. 创建任务接口完成校验和落库后立即返回，不等待制作结束。
5. 后台按照固定顺序执行三个独立阶段，每个阶段均可观察、可持久化。
6. 任务失败后停止后续阶段，并记录失败阶段和可理解的原因。
7. 用户可连续创建多个任务，各任务状态、查询错误和结果互不串扰。
8. 页面刷新后可恢复历史记录，并继续跟踪未完成任务。

### 2.2 工程目标

- 使用清晰的前后端边界，业务执行和持久化均由 Java 负责。
- 关键状态转换具有测试保护。
- 配置中不包含真实密码、密钥或其他敏感凭据。
- 推荐通过 `docker compose up --build` 完成一键启动。
- GitHub Actions 在 push 和 pull request 时完成前后端检查与构建。

### 2.3 非目标

本项目不以算法复杂度、微服务数量或基础设施复杂度为目标。完整、可靠、容易复现和容易解释优先于引入更多组件。

## 3. 技术栈

具体补丁版本在项目初始化时写入锁文件和根 README，以下为基线选择：

| 层级 | 技术选择 | 用途 |
|---|---|---|
| 前端 | Next.js App Router、React、TypeScript | 页面、路由及交互 |
| UI | CSS Modules 或 Tailwind CSS（二选一，初始化时固定） | 响应式样式 |
| 服务端状态 | TanStack Query | 请求缓存、轮询和失效控制 |
| 前端测试 | Vitest、React Testing Library | 多任务和异常状态测试 |
| 后端 | Java 21、Spring Boot 3.x | REST API、认证、异步执行 |
| 安全 | Spring Security、BCrypt、JWT | 登录认证和接口保护 |
| 持久层 | MyBatis、Flyway | SQL 映射和数据库迁移 |
| 数据库 | MySQL 8.x | 用户、模板、素材和任务持久化 |
| 后端测试 | JUnit 5、Mockito、Spring Boot Test、Testcontainers（按需） | 单元与集成测试 |
| 构建 | Maven Wrapper、npm | 可复现构建 |
| 交付 | Docker、Docker Compose、GitHub Actions | 容器运行和 CI |

技术取舍：

- 使用轮询而非 SSE/WebSocket，足以满足任务状态更新需求，生命周期更易测试。
- 使用 Spring 管理的有界线程池，不直接 `new Thread()`，避免无控制地创建线程。
- 使用 JWT Bearer Token 简化前后端分离认证。仅提供短期访问令牌，不实现刷新令牌。
- 上传文件存放于后端本地目录/容器数据卷，MySQL 仅保存文件元数据。

## 4. 系统架构

### 4.1 逻辑架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Next.js                                                      │
│ 登录 / 模板列表 / 模板详情上传 / 我的制作                    │
│ TanStack Query：接口缓存、未完成任务轮询、请求清理            │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTP + JSON / multipart/form-data
                           │ Authorization: Bearer <JWT>
┌──────────────────────────▼───────────────────────────────────┐
│ Spring Boot                                                  │
│ Controller → Application Service → MyBatis Mapper            │
│                    │                                         │
│                    └→ Task Executor → 三阶段任务处理器        │
└───────────────┬────────────────────────────┬─────────────────┘
                │                            │
        ┌───────▼────────┐          ┌────────▼─────────┐
        │ MySQL          │          │ 本地/容器数据卷   │
        │ 业务状态与记录 │          │ 上传图片          │
        └────────────────┘          └──────────────────┘
```

### 4.2 后端分层

```text
controller     HTTP 协议、参数解析、返回 DTO
application    用例编排：登录、上传、创建任务、查询任务
domain         状态枚举、业务规则、阶段处理接口
infrastructure MyBatis、文件存储、JWT、线程池和配置
```

控制器不直接编写 SQL，不直接执行长耗时任务。任务查询接口只读取状态，不驱动状态前进。

### 4.3 异步任务执行

创建任务采用“先落库、再提交执行”的顺序：

1. 校验模板、素材数量、素材归属和文件存在性。
2. 在事务内插入 `production_task` 和 `production_task_asset`。
3. 事务成功提交后，把 `taskId` 提交给 Spring `ThreadPoolTaskExecutor`。
4. HTTP 接口返回 `202 Accepted`。
5. 后台执行器依据 `taskId` 重新读取数据库并执行三个阶段。

线程池建议初始配置：

```text
corePoolSize = 2
maxPoolSize = 4
queueCapacity = 100
threadNamePrefix = production-task-
```

若线程池队列已满，创建接口不能留下永远不执行的任务。最小方案是在提交执行失败时将任务更新为 `FAILED`，失败原因记为“任务执行队列已满”，并向客户端返回明确错误；具体原子性在实现阶段通过服务方法和补偿更新保证。

### 4.4 状态机

整体状态：

```text
QUEUED → PROCESSING → SUCCEEDED
                    ↘ FAILED
QUEUED ─────────────→ FAILED
```

处理阶段：

```text
MATERIAL_CHECK → GENERATING → FINALIZING
```

约束：

- `SUCCEEDED` 和 `FAILED` 为终态，不允许回到 `PROCESSING`。
- 阶段只能按规定顺序前进。
- 进入每一步前，先持久化 `PROCESSING + 当前阶段`。
- 任一步抛出业务异常或非预期异常时，保存 `FAILED + 当前阶段 + 失败原因`，后续步骤不执行。
- 结果整理成功后保存结果地址、完成时间和 `SUCCEEDED`。

### 4.5 认证设计

1. 用户通过用户名和密码调用登录接口。
2. 后端查询 `app_user`，使用 BCrypt 校验密码哈希。
3. 登录成功后签发包含 `userId`、`username`、过期时间的 JWT。
4. 前端后续请求使用 `Authorization: Bearer <token>`。
5. 后端从认证上下文取得用户 ID，不能接受客户端传入的 `userId` 作为数据归属依据。
6. 前端退出登录时删除本地令牌；本期不实现服务端令牌撤销和刷新令牌。

演示账号通过 Flyway 初始化脚本创建，README 提供非敏感的演示用户名和密码。仓库中只保存 BCrypt 哈希，不保存生产凭据。

### 4.6 文件存储

- 模板封面和模拟结果为项目内公开演示资源。
- 用户上传图片存放到配置目录，例如 `/data/uploads/{userId}/{uuid}.jpg`。
- 数据库保存相对存储键，不保存 Windows 或 Linux 绝对路径。
- 用户素材内容通过受认证接口读取，并验证素材归属；前端获取 Blob 后生成临时预览 URL。
- Docker Compose 使用命名数据卷保存上传文件。

## 5. 数据库设计

### 5.1 数据库基本信息

- 数据库名：`view_gene`
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_0900_ai_ci`
- 时区：应用和数据库统一使用 UTC 存储，接口返回 ISO 8601；前端按本地时区展示。
- 迁移工具：Flyway，禁止依赖手工建表作为唯一初始化方式。

命名约定：表名和字段名使用 `snake_case`；主键使用 `BIGINT UNSIGNED`；时间字段使用 `DATETIME(3)`。

### 5.2 `app_user` 用户表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 用户ID |
| username | VARCHAR(64) | NOT NULL | 登录名 |
| display_name | VARCHAR(64) | NOT NULL | 展示名称 |
| password_hash | VARCHAR(100) | NOT NULL | BCrypt 哈希 |
| status | VARCHAR(16) | NOT NULL | `ACTIVE`/`DISABLED` |
| created_at | DATETIME(3) | NOT NULL | 创建时间 |
| updated_at | DATETIME(3) | NOT NULL | 更新时间 |

索引与约束：

- `PRIMARY KEY (id)`
- `UNIQUE KEY uk_app_user_username (username)`
- `CHECK (status IN ('ACTIVE','DISABLED'))`

### 5.3 `template_category` 模板分类表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 分类ID |
| code | VARCHAR(32) | NOT NULL | 稳定编码 |
| name | VARCHAR(64) | NOT NULL | 展示名称 |
| sort_order | INT | NOT NULL, DEFAULT 0 | 排序 |
| enabled | TINYINT(1) | NOT NULL, DEFAULT 1 | 是否启用 |

索引与约束：

- `UNIQUE KEY uk_template_category_code (code)`
- `CHECK (enabled IN (0,1))`

### 5.4 `material_template` 模板表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | VARCHAR(64) | PK | 如 `travel-postcard` |
| category_id | BIGINT UNSIGNED | FK, NOT NULL | 所属分类 |
| title | VARCHAR(128) | NOT NULL | 标题 |
| description | VARCHAR(1000) | NOT NULL | 描述 |
| cover_url | VARCHAR(500) | NOT NULL | 示例封面 |
| result_url | VARCHAR(500) | NOT NULL | 模拟成功结果图 |
| required_image_count | INT UNSIGNED | NOT NULL | 要求图片数 |
| accepted_mime_types | JSON | NOT NULL | MIME 类型数组 |
| max_file_size_bytes | BIGINT UNSIGNED | NOT NULL | 单文件上限 |
| enabled | TINYINT(1) | NOT NULL, DEFAULT 1 | 是否可用 |
| sort_order | INT | NOT NULL, DEFAULT 0 | 排序 |
| created_at | DATETIME(3) | NOT NULL | 创建时间 |
| updated_at | DATETIME(3) | NOT NULL | 更新时间 |

索引与约束：

- `KEY idx_template_category_enabled_sort (category_id, enabled, sort_order)`
- `FOREIGN KEY (category_id) REFERENCES template_category(id)`
- `CHECK (required_image_count BETWEEN 1 AND 10)`
- `CHECK (max_file_size_bytes > 0)`
- `CHECK (enabled IN (0,1))`

### 5.5 `asset` 上传素材表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 素材ID |
| user_id | BIGINT UNSIGNED | FK, NOT NULL | 所属用户 |
| original_name | VARCHAR(255) | NOT NULL | 原始文件名，仅展示 |
| storage_key | VARCHAR(500) | NOT NULL | 相对存储键 |
| mime_type | VARCHAR(100) | NOT NULL | 服务端识别类型 |
| file_size_bytes | BIGINT UNSIGNED | NOT NULL | 文件大小 |
| sha256 | CHAR(64) | NULL | 内容摘要，便于校验 |
| status | VARCHAR(16) | NOT NULL | `READY`/`INVALID` |
| created_at | DATETIME(3) | NOT NULL | 上传时间 |

索引与约束：

- `UNIQUE KEY uk_asset_storage_key (storage_key)`
- `KEY idx_asset_user_created (user_id, created_at DESC)`
- `FOREIGN KEY (user_id) REFERENCES app_user(id)`
- `CHECK (file_size_bytes > 0)`
- `CHECK (status IN ('READY','INVALID'))`

### 5.6 `production_task` 制作任务表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 任务ID |
| user_id | BIGINT UNSIGNED | FK, NOT NULL | 所属用户 |
| template_id | VARCHAR(64) | FK, NOT NULL | 使用模板 |
| status | VARCHAR(16) | NOT NULL | 整体状态 |
| stage | VARCHAR(32) | NULL | 当前/失败阶段 |
| result_url | VARCHAR(500) | NULL | 成功结果地址 |
| failure_code | VARCHAR(64) | NULL | 稳定失败编码 |
| failure_reason | VARCHAR(1000) | NULL | 可展示失败原因 |
| created_at | DATETIME(3) | NOT NULL | 创建时间 |
| started_at | DATETIME(3) | NULL | 开始时间 |
| completed_at | DATETIME(3) | NULL | 完成时间 |
| updated_at | DATETIME(3) | NOT NULL | 更新时间 |
| version | INT UNSIGNED | NOT NULL, DEFAULT 0 | 乐观锁版本 |

索引与约束：

- `KEY idx_task_user_created (user_id, created_at DESC)`：个人历史。
- `KEY idx_task_user_status_updated (user_id, status, updated_at)`：查询个人未完成任务。
- `KEY idx_task_status_created (status, created_at)`：后台排查和未来恢复扩展。
- `FOREIGN KEY (user_id) REFERENCES app_user(id)`
- `FOREIGN KEY (template_id) REFERENCES material_template(id)`
- `CHECK (status IN ('QUEUED','PROCESSING','SUCCEEDED','FAILED'))`
- `CHECK (stage IS NULL OR stage IN ('MATERIAL_CHECK','GENERATING','FINALIZING'))`

应用层还需保证：

- `SUCCEEDED` 时 `result_url` 和 `completed_at` 非空。
- `FAILED` 时 `failure_code`、`failure_reason` 和 `completed_at` 非空。
- `QUEUED` 时 `stage`、`started_at` 和 `completed_at` 为空。
- 只有符合当前状态和 `version` 的条件更新才能成功，防止旧线程覆盖终态。

### 5.7 `production_task_asset` 任务素材关联表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| task_id | BIGINT UNSIGNED | PK, FK | 任务ID |
| position | INT UNSIGNED | PK | 上传位顺序，从1开始 |
| asset_id | BIGINT UNSIGNED | FK, NOT NULL | 素材ID |

索引与约束：

- `PRIMARY KEY (task_id, position)`：同一位置只能有一个素材。
- `UNIQUE KEY uk_task_asset (task_id, asset_id)`：同一任务不重复引用素材。
- `KEY idx_task_asset_asset_id (asset_id)`
- 外键分别关联任务和素材。
- `CHECK (position BETWEEN 1 AND 10)`

### 5.8 删除策略

本期不提供删除接口。数据库外键默认 `RESTRICT`，不级联删除用户、模板、素材和任务，以免破坏历史记录。测试数据重置通过专用迁移或重新创建容器数据卷完成，不通过业务接口完成。

## 6. 数据实体与通用模型

### 6.1 后端领域实体

```text
User
  id, username, displayName, passwordHash, status, createdAt, updatedAt

TemplateCategory
  id, code, name, sortOrder, enabled

MaterialTemplate
  id, categoryId, title, description, coverUrl, resultUrl,
  requiredImageCount, acceptedMimeTypes, maxFileSizeBytes, enabled

Asset
  id, userId, originalName, storageKey, mimeType,
  fileSizeBytes, sha256, status, createdAt

ProductionTask
  id, userId, templateId, status, stage, resultUrl,
  failureCode, failureReason, createdAt, startedAt,
  completedAt, updatedAt, version

ProductionTaskAsset
  taskId, position, assetId
```

数据库实体、接口请求 DTO 和接口响应 DTO 分离，避免直接把 `password_hash`、`storage_key` 等内部字段返回前端。

### 6.2 枚举

```text
UserStatus       ACTIVE, DISABLED
AssetStatus      READY, INVALID
TaskStatus       QUEUED, PROCESSING, SUCCEEDED, FAILED
TaskStage        MATERIAL_CHECK, GENERATING, FINALIZING
FailureStage     NONE, MATERIAL_CHECK, GENERATING, FINALIZING（仅配置使用）
```

### 6.3 通用成功响应

单对象接口统一使用：

```json
{
  "data": {},
  "requestId": "8db5d470...",
  "timestamp": "2026-11-08T10:30:00.000Z"
}
```

列表接口：

```json
{
  "data": {
    "items": [],
    "total": 0
  },
  "requestId": "8db5d470...",
  "timestamp": "2026-11-08T10:30:00.000Z"
}
```

当前数据量较小，模板和历史记录首版可不分页；接口保留稳定列表结构，后续可平滑增加 `page`、`pageSize`。

### 6.4 通用错误响应

```json
{
  "error": {
    "code": "INVALID_ASSET_COUNT",
    "message": "旅行明信片要求上传2张图片",
    "fieldErrors": [
      {
        "field": "assetIds",
        "message": "数量必须为2"
      }
    ]
  },
  "requestId": "8db5d470...",
  "timestamp": "2026-11-08T10:30:00.000Z"
}
```

错误类型：

| HTTP | 错误编码示例 | 含义 |
|---:|---|---|
| 400 | `VALIDATION_ERROR`, `INVALID_ASSET_COUNT` | 请求字段或业务参数错误 |
| 401 | `UNAUTHENTICATED`, `INVALID_CREDENTIALS`, `TOKEN_EXPIRED` | 未登录或登录失效 |
| 403 | `USER_DISABLED`, `ASSET_ACCESS_DENIED` | 已识别但禁止访问 |
| 404 | `TEMPLATE_NOT_FOUND`, `TASK_NOT_FOUND`, `ASSET_NOT_FOUND` | 资源不存在；跨用户查询任务统一按不存在处理 |
| 409 | `TASK_STATE_CONFLICT` | 状态更新冲突 |
| 413 | `FILE_TOO_LARGE` | 文件超限 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 图片类型不支持 |
| 429 | `TASK_QUEUE_FULL` | 后台执行队列已满 |
| 500 | `INTERNAL_ERROR`, `FILE_STORAGE_ERROR` | 非预期错误 |

后端通过全局异常处理器统一转换错误。生产响应不返回 Java 堆栈、SQL、物理文件路径或 JWT 密钥等内部信息。

### 6.5 前端实体

除接口返回的 `TaskDto` 外，前端为界面状态定义独立类型：

```ts
type UploadSlotStatus = 'EMPTY' | 'UPLOADING' | 'SUCCESS' | 'FAILED';

interface UploadSlotState {
  position: number;
  status: UploadSlotStatus;
  previewUrl?: string;
  assetId?: number;
  fileName?: string;
  error?: string;
}

interface TaskViewState {
  task: TaskDto;
  isRefreshing: boolean;
  queryError?: string;
}
```

`task.status === 'FAILED'` 表示后台业务失败；`queryError` 表示本次查询失败，二者不得混用。

## 7. 接口设计

统一约定：

- 基础路径：`/api/v1`。
- JSON 使用 UTF-8 和 `camelCase`。
- 除登录、模板读取和公开演示图片外，接口要求 Bearer Token。
- 资源归属一律从认证用户中获取，不接受请求体中的 `userId`。
- 时间使用带时区的 ISO 8601 字符串。

### 7.1 登录

`POST /api/v1/auth/login`

作用：校验数据库预置用户并签发访问令牌。

请求：

```json
{
  "username": "demo",
  "password": "Demo123!"
}
```

字段：

| 字段 | 必填 | 规则 |
|---|---|---|
| username | 是 | 1～64字符，去除首尾空格 |
| password | 是 | 1～128字符，不写入日志 |

成功 `200`：

```json
{
  "data": {
    "accessToken": "eyJ...",
    "tokenType": "Bearer",
    "expiresInSeconds": 28800,
    "user": {
      "id": 1,
      "username": "demo",
      "displayName": "演示用户"
    }
  },
  "requestId": "...",
  "timestamp": "..."
}
```

处理逻辑：查询用户名；检查用户状态；BCrypt 校验；签发 8 小时访问令牌；返回非敏感用户信息。

注意事项：用户名不存在和密码错误统一返回 `401 INVALID_CREDENTIALS`，避免泄露账号是否存在。登录接口不得记录明文密码。

### 7.2 当前用户

`GET /api/v1/auth/me`

作用：页面刷新时验证令牌并恢复当前用户。

成功 `200` 返回 `id`、`username`、`displayName`。令牌缺失、过期或签名无效返回 `401`。

### 7.3 退出登录

`POST /api/v1/auth/logout`

作用：统一前端退出流程。首版返回 `204 No Content`，前端删除访问令牌、停止轮询并清空用户级缓存。

注意事项：JWT 首版不建立撤销列表，因此服务端不能立即使已签发令牌失效；这是已知限制，README 必须说明。

### 7.4 模板分类与列表

`GET /api/v1/templates?categoryCode=travel`

作用：读取启用分类和模板卡片；`categoryCode` 可选。

响应字段：

```json
{
  "data": {
    "categories": [
      { "code": "travel", "name": "旅行" }
    ],
    "items": [
      {
        "id": "travel-postcard",
        "title": "旅行明信片",
        "categoryCode": "travel",
        "categoryName": "旅行",
        "coverUrl": "/demo/templates/postcard-cover.jpg",
        "description": "上传两张旅行照片，模拟生成一张明信片",
        "requiredImageCount": 2
      }
    ],
    "total": 1
  },
  "requestId": "...",
  "timestamp": "..."
}
```

处理逻辑：只查询启用分类和启用模板；按分类排序、模板排序返回。分类不存在时返回空列表而非 404。

### 7.5 模板详情

`GET /api/v1/templates/{templateId}`

作用：读取模板完整素材要求。

成功响应 `data`：

```json
{
  "id": "travel-postcard",
  "title": "旅行明信片",
  "categoryCode": "travel",
  "categoryName": "旅行",
  "coverUrl": "/demo/templates/postcard-cover.jpg",
  "description": "上传两张旅行照片，模拟生成一张明信片",
  "requiredImageCount": 2,
  "acceptedMimeTypes": ["image/jpeg", "image/png"],
  "maxFileSizeBytes": 5242880
}
```

处理逻辑：按 ID 查询启用模板；不存在或已禁用返回 `404 TEMPLATE_NOT_FOUND`。

### 7.6 上传素材

`POST /api/v1/assets`

请求类型：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | binary | 是 | 图片文件 |
| templateId | string | 是 | 用于按模板规则校验 |

成功 `201`：

```json
{
  "data": {
    "id": 101,
    "originalName": "travel.jpg",
    "mimeType": "image/jpeg",
    "fileSizeBytes": 2458201,
    "contentUrl": "/api/v1/assets/101/content",
    "createdAt": "2026-11-08T10:20:00.000Z"
  },
  "requestId": "...",
  "timestamp": "..."
}
```

处理逻辑：

1. 从认证上下文取得用户。
2. 查询启用模板。
3. 校验非空、大小上限和允许 MIME 类型；不能只信任文件扩展名。
4. 生成不可预测的 UUID 存储名，规范化原始文件名，禁止路径穿越。
5. 写入临时文件，计算摘要并原子移动到目标位置。
6. 文件保存成功后插入 `asset`；数据库失败则清理已写文件。
7. 返回素材 ID，不返回物理路径。

注意事项：Spring Multipart 全局上限应不小于模板最大上限；前端校验不能替代后端校验。

### 7.7 读取素材内容

`GET /api/v1/assets/{assetId}/content`

作用：登录用户预览自己的上传素材。

处理逻辑：查询素材并验证 `asset.user_id == currentUser.id`；读取存储键对应文件；设置正确的 `Content-Type` 和缓存头。跨用户访问统一返回 `404 ASSET_NOT_FOUND`。

### 7.8 创建制作任务

`POST /api/v1/tasks`

请求：

```json
{
  "templateId": "travel-postcard",
  "assetIds": [101, 102]
}
```

字段：

| 字段 | 必填 | 规则 |
|---|---|---|
| templateId | 是 | 启用模板 ID |
| assetIds | 是 | 顺序代表上传位；不得重复 |

成功 `202`：

```json
{
  "data": {
    "id": 9001,
    "status": "QUEUED",
    "stage": null,
    "createdAt": "2026-11-08T10:30:00.000Z"
  },
  "requestId": "...",
  "timestamp": "..."
}
```

处理逻辑：

1. 读取认证用户和启用模板。
2. 校验素材 ID 数量等于模板要求，且不存在重复 ID。
3. 一次查询取得全部素材，校验数量完整、归属当前用户、状态为 `READY`。
4. 重新校验 MIME、大小和物理文件存在性，防止绕过上传接口或文件丢失。
5. 事务内写入 `QUEUED` 任务和有序关联记录。
6. 事务提交后提交后台执行；接口不等待三阶段结束。
7. 返回任务 ID 和初始状态。

注意事项：提交按钮在请求中需禁用，但首版不保证网络重试下的严格幂等；该边界写入 README。

### 7.9 查询个人任务列表

`GET /api/v1/tasks?status=PROCESSING`

作用：加载个人历史和刷新恢复；`status` 可选。默认按 `createdAt DESC` 返回当前用户全部任务。

任务响应字段：

```json
{
  "id": 9001,
  "template": {
    "id": "travel-postcard",
    "title": "旅行明信片",
    "coverUrl": "/demo/templates/postcard-cover.jpg"
  },
  "status": "PROCESSING",
  "stage": "GENERATING",
  "resultUrl": null,
  "failure": null,
  "createdAt": "2026-11-08T10:30:00.000Z",
  "startedAt": "2026-11-08T10:30:01.000Z",
  "completedAt": null,
  "updatedAt": "2026-11-08T10:30:04.000Z"
}
```

失败任务的 `failure`：

```json
{
  "code": "SIMULATED_GENERATION_FAILURE",
  "message": "已按模拟配置触发生成失败",
  "stage": "GENERATING"
}
```

处理逻辑：查询条件必须包含认证用户 ID。前端只对 `QUEUED`、`PROCESSING` 任务继续轮询。

### 7.10 查询单个任务

`GET /api/v1/tasks/{taskId}`

作用：轮询任务最新状态。

处理逻辑：按 `taskId + currentUserId` 查询；不存在或属于其他用户均返回 `404 TASK_NOT_FOUND`。本接口只读取数据库，不触发任务处理，不修改阶段。

### 7.11 读取成功结果

成功任务的 `resultUrl` 指向项目预置结果图片，例如 `/demo/results/travel-postcard.jpg`。若实现为受保护结果接口，则使用：

`GET /api/v1/tasks/{taskId}/result`

读取前必须验证任务属于当前用户且状态为 `SUCCEEDED`。首版建议预置结果公开、上传原图受保护，以降低前端图片展示复杂度，并在 README 说明演示资源边界。

### 7.12 健康检查

`GET /actuator/health`

作用：Docker Compose 健康检查和运行验收。生产式响应不暴露敏感配置。

## 8. 模拟处理配置

通过环境变量或 Spring 配置控制，不要求正式 UI：

```text
SIMULATION_FAILURE_STAGE=NONE
SIMULATION_MATERIAL_CHECK_DELAY_MS=3000
SIMULATION_GENERATING_DELAY_MS=5000
SIMULATION_FINALIZING_DELAY_MS=2000
```

`SIMULATION_FAILURE_STAGE` 可取：

```text
NONE
MATERIAL_CHECK
GENERATING
FINALIZING
```

所有延迟设置合理上限，例如 0～60000 ms，避免错误配置长期占用线程。指定阶段失败必须稳定复现，不使用随机失败。

## 9. 前端页面与状态设计

### 9.1 路由

```text
/login                    登录页
/                         模板列表页
/templates/[templateId]   模板详情与上传页
/tasks                    我的制作/历史任务页
```

未登录访问业务页时跳转 `/login`；令牌过期时停止轮询、清除用户缓存并返回登录页。

### 9.2 页面验收点

登录页：登录中禁用按钮；展示统一凭据错误；不提供注册入口。

模板列表：加载、成功、空数据、失败重试；分类切换；卡片进入详情。

模板详情：模板不存在；动态上传位；预览、替换、移除；每个上传位独立状态；全部上传成功后才允许提交；提交成功后进入“我的制作”。

我的制作：按时间倒序；展示等待、三个处理阶段、成功结果和失败原因；查询失败保留上一次任务状态；提供手动刷新。

### 9.3 轮询策略

- 页面加载时获取个人任务列表。
- 存在 `QUEUED` 或 `PROCESSING` 任务时，每 2～3 秒刷新。
- 某任务进入 `SUCCEEDED` 或 `FAILED` 后停止跟踪该任务。
- 没有未完成任务时停止轮询。
- 页面卸载、退出登录和用户变化时取消查询并清除相应缓存。
- 查询错误保存为 `queryError`，不能将任务改成 `FAILED`。

## 10. 测试方案

### 10.1 后端关键测试

必须覆盖：

1. 正常任务严格按素材检查、模拟生成、结果整理的顺序执行。
2. 每个指定阶段失败后，后续阶段不执行。
3. 失败阶段、错误编码和错误原因被持久化。
4. 成功和失败终态不会被旧更新改回处理中。
5. 创建任务验证素材数量、归属、类型、大小和文件存在性。
6. 查询接口不会驱动任务推进。
7. 用户不能查询其他用户的任务和素材。
8. 登录密码使用 BCrypt 校验，禁用用户不能登录。

### 10.2 前端关键测试

必须覆盖：

1. 多个任务各自更新，不互相覆盖。
2. 查询请求失败不改变后台任务业务状态。
3. 单个任务终止后不再跟踪；全部终止后停止轮询。
4. 刷新加载历史后继续跟踪未完成任务。
5. 上传位状态互相独立，未全部成功时不能提交。
6. 登录失效后停止旧请求并跳转登录页。

### 10.3 非强制测试

不要求完整浏览器 E2E；如时间允许，可增加一条登录到任务成功的 Playwright 冒烟测试。

## 12. 安全与可靠性注意事项

- 密码只保存 BCrypt 哈希；JWT 密钥从环境变量读取。
- 登录和上传接口应设置合理限流属于生产建议，本期可记录但不强制实现。
- 文件名由服务端生成；不信任扩展名和客户端 MIME；限制请求和文件大小。
- SQL 使用 MyBatis 参数绑定，禁止字符串拼接用户输入。
- 日志不输出密码、完整令牌和文件内容。
- 任务状态采用条件更新/乐观锁，避免较晚的旧更新覆盖终态。
- 跨用户资源查询尽量返回 404，减少资源枚举信息泄露。
- 前端本地保存 JWT 存在 XSS 风险；本期配合短有效期和避免危险 HTML 注入，生产方案优先考虑 HttpOnly Secure Cookie/BFF。

## 13. 已知限制与明确取舍

1. 服务进程重启后，数据库中的未完成任务仍可见，但首版不保证自动恢复执行。
2. JWT 退出登录只清理客户端令牌，令牌在过期前理论上仍有效。
3. 不提供严格的任务创建幂等键，极端网络重试可能创建重复任务。
4. 文件使用单机/数据卷存储，不适用于多实例共享。
5. 模拟结果来自预置图片，不代表真实图片生成能力。
6. 不实现素材垃圾回收；未被任务引用的上传文件可能保留，作为后续扩展讨论。

这些限制均属于题目允许的范围，必须在最终 README 如实说明。
